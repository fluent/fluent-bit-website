###### KNOWLEDGE BASE

## Release Notes v5.2.0

[Fluent Bit](https://fluentbit.io) is a Fast and Lightweight Telemetry Agent for Linux, BSD, macOS and Windows. We are proud to announce the availability of **Fluent Bit v5.2.0**.

Fluent Bit 5.2 brings typed, programmable processing to logs, metrics, and traces with **Fluent Typed Scripting (FTS)**. It accelerates OpenTelemetry log pipelines, improves buffering efficiency, adds journald-to-OpenTelemetry mapping, and makes delivery more responsive to destination backpressure.

### What's new ?

<br>

#### FTS: a native telemetry processor, scripted with Lua

[Fluent Typed Scripting](/fts/) is a new native Fluent Bit processor for logs, metrics, and traces. Lua expresses your policy; FTS manages typed telemetry values, OpenTelemetry context, and how changes are committed or rolled back.

Unlike the existing Lua log filter, FTS processes all three signals and exposes typed values directly. Large integer IDs, nulls, and binary data retain their meaning when a policy changes another field. Resource and instrumentation context are available as named properties.

Use FTS to redact known fields, normalize telemetry, or reduce unwanted events and metric dimensions. Existing Lua filter scripts remain supported; migrating to FTS requires adapting their API.

#### Faster pipelines, with measurements you can inspect

In the published memory-buffered OTLP/HTTP JSON transformation benchmark, Fluent Bit 5.2 reaches **1.50 million records/s**: **7.2× the throughput of 5.1** and **2.0× Collector 0.163** for the same log-attribute update. These comparisons use native content modifier processing in Fluent Bit.

The separate FTS scripting benchmarks show **18–45% less CPU than equivalent Lua log policies on 5.1.0**. Compatible content modifier chains also benefit from performing multiple edits in one pass.

The [5.2 benchmark report](/benchmarks/5.2/) includes CPU, memory, latency, buffering conditions, and tradeoffs. These figures describe specific workloads, not a guaranteed production rate.

#### System logs ready for OpenTelemetry

The new `journald_otel` processor maps journal records into OpenTelemetry logs, including severity, host and process information. This makes system logs easier to query alongside application telemetry without building a custom field-mapping script.

#### More considerate delivery under pressure

HTTP, OpenTelemetry, Elasticsearch, and OpenSearch outputs recognize destination throttling and supported retry-delay hints. The engine can wait for a destination to recover without spending retry attempts simply because a cooldown is active, helping pipelines respond more predictably to busy services.

### Core

<br>

- **Processing:** accelerate eligible OTLP log pipelines and compatible content modifier chains, while preserving grouped telemetry and exact record accounting.
- **Buffering:** improve filesystem allocation for low-volume streams and process large log buffers in bounded windows. The sparse-stream benchmark reduces allocated disk by 92.2%; busy-stream results and tradeoffs are included in the benchmark report.
- **Delivery:** coordinate output cooldowns, queued work, and shutdown more reliably, and keep outputs making progress during heavy threaded ingestion.
- **Configuration:** prefer paths relative to the configuration file for includes, parsers, scripts, and auxiliary files; add YAML configuration generation from command-line options.
- **Reliability:** improve HTTP resource controls, regular-expression handling, TLS configuration consistency, and Windows and macOS lifecycle behavior.
- **Validation:** expand integration coverage for typed processing, backpressure, configuration portability, protocol handling, and cloud delivery.

### Libraries

<br>

- Update **CFL to v1.1.0**, **CMetrics to v2.3.1**, and **CTraces to v0.8.0**.
- Update **ChunkIO to v1.5.5** and **yyjson to v0.13.0**.
- Refresh LuaJIT, Onigmo, and SQLite for compatibility, portability, and more predictable resource use.

### Plugins

<br>

#### Inputs

- **OpenTelemetry:** accelerate JSON and Protobuf log processing across eligible native processor chains and improve connection distribution across HTTP workers.
- **Node Exporter Metrics:** add an optional immediate scrape at startup and improve textfile metric collection.
- **Tail, Forward, Syslog, and Unix Socket:** improve recovery, shutdown, grouped-log handling, and local socket lifecycle behavior.

#### Processors & Filters

- **FTS:** introduce typed policies for all three telemetry signals, OpenTelemetry-aware helpers, JSON decoding, and configurable error handling.
- **Journald OpenTelemetry:** add native journal-to-OpenTelemetry field mapping.
- **Content Modifier and SQL:** improve native processing efficiency and preserve telemetry grouping through transformations.
- **WebAssembly:** add the v2 value-length interface, with C, Rust, and TinyGo filter examples.

#### Outputs

- **HTTP, OpenTelemetry, Elasticsearch, and OpenSearch:** honor supported throttling responses and retry hints.
- **VIVO:** expand live telemetry inspection with versioned OTLP JSON streams, bounded retention, and gzip responses. Retained inspection data is temporary.
- **Kafka and File:** improve serialization validation and output correctness for Avro, Protobuf, CSV, and LTSV.
- **Prometheus Exporter:** group repeated metric families consistently.

#### Experimental browser SDK

An embeddable JavaScript SDK runs the Fluent Bit engine in a browser through WebAssembly. It provides configuration, JSON log ingestion, and lifecycle controls for browser applications. This is a separate, experimental build profile with its own deployment requirements and support limits.

### Upgrading

<br>

- Review relative file paths: configuration-directory paths now take precedence for supported configuration assets.
- VIVO listens on `127.0.0.1` by default. Set an explicit listener address if remote access is required, and protect remote access appropriately.
- Existing Lua filter policies continue to work. Choose FTS for typed, multi-signal processing and adapt scripts to its callback and value model when migrating.
