###### KNOWLEDGE BASE

## Release Notes v5.2.1

[Fluent Bit](https://fluentbit.io) is a Fast and Lightweight Telemetry Agent for Linux, BSD, macOS and Windows. We are proud to announce the availability of **Fluent Bit v5.2.1**.

If you are upgrading from a previous version, consult the [Upgrading Notes](https://docs.fluentbit.io/manual/installation/upgrade-notes).

Fluent Bit v5.2.1 is a maintenance release that adds reusable YAML defaults, expands the experimental browser SDK to accept OpenTelemetry metrics and traces, and improves delivery during backpressure and restarts. It also adds a native CRI parser, completes MQTT QoS 2 handling, and makes record timestamps configurable in Google Cloud Storage output.

The release contains 141 commits since v5.2.0, with improvements across configuration, log processing, inputs, filters, outputs, packaging, and test coverage.

For users upgrading from earlier series, Fluent Bit 5.2 also includes Fluent Typed Scripting for logs, metrics, and traces, OTLP JSON streams in VIVO, and optional encoding of NATS tags as valid publish subjects. [Fluent Bit v5.2.0 release notes](/announcements/v5.2.0/)

### What's new ?

<br>

### Core

<br>

- configuration — reuse settings across YAML includes with a top-level `defaults` mapping, anchors, aliases, and explicit mapping merges. Improve syntax diagnostics and fix loading YAML upstream groups for high availability. [YAML composition guide](https://github.com/fluent/fluent-bit/blob/v5.2.1/docs/configuration/yaml-composition.md)
- parsing — add a native `cri` format and use it in the built-in CRI multiline parser to reduce container log parsing overhead
- processing — reduce overhead for ungrouped log batches
- delivery — account for deferred output routes when applying input backpressure and preserve shutdown failures across pipeline reloads
- TLS — verify AWS container credential endpoints and improve recovery when Windows needs to update its trusted roots. [Windows TLS behavior](https://github.com/fluent/fluent-bit/blob/v5.2.1/docs/windows-tls.md)
- browser SDK — accept OTLP JSON metrics and traces alongside logs, evaluate routing conditions, inspect the resolved pipeline topology, and trace a record through the pipeline
- container images — rebuild maintained releases with updated base images and provide dated tags and digests for pinning a specific build. [Container image index](https://github.com/fluent/fluent-bit/wiki/Container-Images)
- tests — expand coverage for YAML composition, container log parsing, Windows TLS, output backpressure, cloud delivery, and browser SDK ingestion and routing

### Libraries

<br>

- WebAssembly Micro Runtime (WAMR) — fix 64-bit compatibility on Windows

### Plugins

<br>

#### Inputs

- **[Tail](https://docs.fluentbit.io/manual/data-pipeline/inputs/tail)**
  - add opt-in file path containment
- **[Blob](https://docs.fluentbit.io/manual/data-pipeline/inputs/blob)**
  - fix ingestion without a tracking database and add opt-in file path containment
- **[Forward](https://docs.fluentbit.io/manual/data-pipeline/inputs/forward)**
  - improve validation of compressed input batches
- **[MQTT](https://docs.fluentbit.io/manual/data-pipeline/inputs/mqtt)**
  - complete the QoS 2 handshake and improve subscription and unsubscription responses
- **Calyptia Fleet**
  - add opt-in file path containment for fleet-managed files

#### Processors & Filters

- **[Kubernetes](https://docs.fluentbit.io/manual/data-pipeline/filters/kubernetes)**
  - preserve metadata enrichment when a bearer token ends with a line break

#### Outputs

- **[Google Cloud Storage](https://docs.fluentbit.io/manual/data-pipeline/outputs/gcs)**
  - configure the record timestamp field and format with `json_date_key` and `json_date_format`. The default is an ISO 8601 timestamp in the `date` field
- **[Amazon S3](https://docs.fluentbit.io/manual/data-pipeline/outputs/s3)**
  - preserve upload cooldowns and retry state when recovering buffered uploads after a restart
  - add opt-in file path containment for blob uploads
- **[Kafka](https://docs.fluentbit.io/manual/data-pipeline/outputs/kafka)**
  - improve dynamic topic routing when multiple output workers are active
- **[File](https://docs.fluentbit.io/manual/data-pipeline/outputs/file)**
  - add opt-in support for dynamic Windows paths with a fixed absolute base directory
  - add opt-in file path containment for writes and rotation
- **[Azure Blob](https://docs.fluentbit.io/manual/data-pipeline/outputs/azure_blob)**
  - add opt-in file path containment for blob uploads and improve file registration reliability
